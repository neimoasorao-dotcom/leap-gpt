# LEAP：UI・操作・モーションの現状分析と実装方針

分析対象は `393c3b4` の `index.html`。以下はコードを確認した時点の設計記録であり、実装後のブラウザ検証の合格を示すものではない。

## 目的と維持する条件

大学受験の英単語を毎日学ぶために、操作結果・現在の状態・次の行動が分かる動きを加える。学習中の集中、iPhoneでの操作、既存の配色・画面構成を優先する。演出のために操作の完了を遅らせない。

- `WORDS`、`EXAMPLES`、`IPA` の教材内容は変更しない。
- 学習スロットの保存形式 `v: 1`、JSONエクスポート `version: 3`、旧データの移行処理を維持する。
- `history`、`missRec`、`marks`、`upd`、`studyPos`、`daily`、`sessions`、`wstat`、`masteryN`、`masteryAt`、`ranges`、`lastAnswerAt` を、表示上の演出で変更しない。
- 最大8スロット、GitHub同期、読み上げ、範囲引き継ぎ、解答途中の画面移動を維持する。
- 一覧をクリックしたときのスクロール位置保持、PCでの横スクロール防止、20px／22pxの学習設定アイコンを維持する。
- 公開URLを変えず、追加の有料サービス・アカウント・本番向け依存ライブラリを必要としない。
- 追加するCSS・JavaScriptは相対パスの通常のローカルファイルとする。classic scriptを使い、ES Modules、初期教材の `fetch()`、ビルド必須の構成へ変更しない。`file://` でHTMLを開く利用を保つ。

## 現在の構造と課題

静的な単一HTMLに教材・CSS・画面処理・保存・同期が入っている。`showSection()` が7画面を切り替え、各 `render...()` が必要な領域を `innerHTML` で更新する。進行中のテストはDOMを残して再開する。データと採点は現在の関数を利用し、表示・操作の共通層を追加する構成が適している。

現状の動きはボタン押下、進捗バー、スター通知、学習のスワイプなどに分散している。共通の時間・easing・動きを減らす設定がなく、ページやカードの出現、保存・追加・編集の結果が突然変わる。設定の操作はブラウザ標準の `alert()`、`confirm()`、`prompt()` が多い。単語検索は入力ごとに結果テーブルを再構築し、候補の提示がない。

教材はページ内にあるため、初期表示に通信待ちはない。Skeletonのために架空の読み込み待ちを作る必要はない。実際の非同期処理はGitHubへの接続・同期、JSONファイルの読み込みなどに存在する。

## 実装の分担と接続点

### 共通モーション層

モーション担当がCSS変数と小さなclassic scriptの共通層を担当する。

- Microは約100〜160ms、Componentは180〜240ms、Pageは240〜300msを基準とする。Emphasisはスター・得点などに一度だけ使う。
- `transform` と `opacity` を中心にし、常時動く装飾・無制限のstagger・`transition: all` の追加を避ける。
- ページ、結果、タブ、カード、数値、進捗、グラフ、可視要素の登場を共通の方法で扱う。
- 新しいDOMへ必要な処理を付ける際は一度だけ初期化する。数値表示のために毎フレームDOMを再生成しない。
- 固定ナビ・学習の固定操作列を含む祖先にtransformを掛けない。学習画面の移動は固定要素を含まない内容側に限定する。
- グラフや数値の保存値・アクセシブルな値は最終値を維持する。演出中の一時値を保存しない。

### 検索・Autocomplete層

検索担当は一覧の入力補助と候補UIを担当する。

- `renderWordList()`、`listSearch()`、`buildWordListBody()` を利用し、検索入力欄を入力ごとに作り直さない。
- 英単語・意味の部分一致、最近の入力、選択頻度を使った候補を上限付きで表示する。教材の表記を書き換えない。
- IMEのcomposition中に確定処理をしない。候補は `combobox`／`listbox` の関係を持ち、上下キー・Enter・Escapeとタッチで選択できる。
- 頻度・履歴は少量の端末別UI設定として扱い、学習スロットや同期スキーマに混ぜない。トークン等の機密入力には候補や履歴を付けない。
- 全2,300行へ個別リスナーや演出を追加せず、イベント委譲と表示範囲の処理を利用する。

### 操作・フィードバック層

親担当がToast・Bottom Sheet・Pull to Refresh・Swipe Action・Skeletonと既存関数への接続を担当する。

- 保存・追加・名前変更・複製・削除・インポート・同期の結果をToastで知らせる。通常の自動保存・毎問の正答では通知を乱発しない。
- Sheetは1つの共通コンテナで表示し、見出し・閉じるボタン・Escape・背景タップ・フォーカストラップ・閉じた後のフォーカス復帰を備える。
- Sheet内の入力は元の検証・保存処理へ渡し、複製したDOMに同じIDを残さない。背景スクロールのロックと解除を対で実装する。
- Pull to Refreshは画面上端・縦方向優勢・1本指・閾値到達を条件にする。内側スクロールが途中、入力・Sheet・解答中なら開始しない。引っ張り中→更新可能→更新中→完了／失敗を同じ小さな領域で示す。
- 同期設定がある場合は現在の同期処理を利用し、ない場合はローカル集計の再表示であることを伝える。ページ全体の再読み込みで進行中の学習を失わせない。
- 一覧の行スワイプはスターを対象にし、縦スクロールや横方向の短い揺れを誤認しない。既存の学習左右移動・回答後の次問スワイプと別のルートで扱う。
- Undoは対象単語の変更だけを戻す。通知後に同じ単語が別の操作で変わっている場合、古いUndoでその変更まで巻き戻さない。
- Skeletonは実際の同期・読み込み状態に結び付ける。最小高さを保ち、長引く場合も閉じる・再試行できる。不要な最低表示時間を設けない。

## 統合時に確認する実装上のリスク

1. `WORDS`、`state`、`syncCfg` などはトップレベルの `const`／`let` であり、`window.WORDS` 等のプロパティには存在しない。追加のclassic scriptは読み込み順を守り、直接参照するか明示的なadapterを使う。
2. 既存の `#content` のMutationObserverは `childList` と `subtree` を監視し、次のフレームで `fitQuizPage()` を呼ぶ。数字やSkeletonを毎フレーム `innerHTML` で書き換えると測定と競合する。Textノードの値・opacity・transformを優先する。
3. `fitStudyLayout()` と `fitQuizPage()` は高さを測って文字・余白を調整する。計測対象の要素へ大きな変形を掛けない。全体遷移で固定ボタンを別の包含ブロックにしない。
4. `speakStudyWord()` はタッチ／クリックと同じ同期処理から読み上げを始める。演出終了やタイマーを待って呼ぶ形に変えない。実際のiPhone音楽との混在再生はブラウザ模擬だけでは保証できない。
5. `syncNow()` は失敗を内部でcatchするため、Promiseがresolveしても成功とは限らない。`syncState.status` の確認なしに完了Toastを出さない。すでに同期中の場合の待機・重複操作も扱う。
6. `writeSlotData()`／`writeSlotIndex()` は失敗時にfalseを返す一方、`saveStorage()` は戻り値を無視している。保存失敗を成功と表示しない。失敗時は安全に再試行・書き出しできる表示が必要である。
7. スロット作成・削除・切替は複数のキーとメモリ状態にまたがる。UIの演出を理由に処理順序を変えず、確認キャンセルでは記録に触れない。
8. スター変更は `touch()`・`upd`・同期にも影響する。見た目だけ先に変更して保存が成功したように扱わない。Undoでも既存の保存・同期の規則を利用する。
9. Bottom Sheetを開閉する前後で、一覧の `scrollTop`、ページの `scrollY`、検索フォーカス、iPhoneキーボードによる表示変化を維持する。

## アクセシビリティとパフォーマンス

- `prefers-reduced-motion` をCSSとJavaScriptの両方で参照し、実行中の設定変更にも追従する。不要な移動・カウントアップ・線の描画・スムーズスクロールを抑制して最終状態を直ちに見せる。
- Toastには通知用のライブ領域を用意し、エラー以外は読み上げを割り込ませない。フォーカスをToastへ強制移動しない。
- Sheetは見出しと説明を持ち、開いている間だけダイアログとして扱う。通常操作・キーボードでも全機能へ到達できるようにする。
- スワイプ・引っ張り・ドラッグにはボタン等の代替操作を残す。取消・縦スクロール・2本指・画面移動を確実に処理する。
- 可視カードだけを一度ずつ演出し、大量リストに無制限なObserver・タイマー・イベントリスナーを残さない。
- JSアニメーションにはAPI未対応時の即時表示を用意する。`animationend`／`transitionend` が来ないと操作やフォーカス復帰が止まる実装を避ける。
- 60fpsは端末実測を伴う目標として扱う。エミュレーションの動作確認だけでiPhone実機のフレームレートを保証しない。

## 実装順序

1. ベースラインのデータ・主要操作・スクロール位置を記録する。
2. 共通モーションとreduced motion、Toast・Sheetの共通UIを追加する。
3. 検索候補、範囲／フィルターSheet、スターのSwipeとUndoを接続する。
4. 実際の同期にSkeletonと更新状態を接続し、安全な画面だけPull to Refreshを有効にする。
5. ページ・結果・状態・統計・グラフへ共通モーションを適用する。
6. 以下の回帰確認を行い、競合を修正してからGitへ記録・公開する。
